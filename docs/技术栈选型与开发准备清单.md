### 核心技术原则

Maple Gateway 不依赖 Nginx 作为必需组件。

默认数据链路：

``` text
Cloudflare for SaaS
        |
        v
   Maple Gateway
        |
        v
 Node / Container
```

Maple Gateway 自身承担：

-   HTTP Gateway
-   Reverse Proxy
-   Tenant Routing
-   Service Discovery
-   Load Balancing
-   Health Awareness
-   Failover
-   Traffic Policy

Fiber 主要用于管理 API，不建议把高性能代理数据平面完全建立在 Fiber
Handler 抽象之上。

### 数据访问原则

请求数据平面不应：

``` text
每个请求 → PostgreSQL 查询 → 再转发
```

应采用：

``` text
PostgreSQL
    ↓
配置同步
    ↓
Memory Route Table
    ↓
请求 O(1) / 低成本查找
```

Redis 是辅助组件，不应成为每个 HTTP 请求的强制依赖。

## 二十一、高可用准备

多 Gateway（v0.1.18 已落地）：

``` text
              Cloudflare
                  |
        +---------+---------+
        |                   |
        v                   v
 Maple Gateway A     Maple Gateway B
        |                   |
        +---------+---------+
                  |
             Node Cluster
```

实现遵循：

-   Gateway Stateless
-   Session 不存本地业务状态
-   Route Cache 可重建
-   Gateway 实例注册 gateway_instances + 心跳，Leader 用 Redis 全局锁（`maple:ha:leader`，DB lease 兜底），故障在 lease 超时后自动接管
-   Instance 状态可重新同步

# 总结

Maple Gateway 技术路线：

**Go + net/http Reverse Proxy + Fiber v3 Management API + PostgreSQL
16 + Memory Route Cache + Redis 7 + Docker**

产品定位：

> 一个面向容器化 SaaS 平台的轻量级 Multi-Tenant Gateway。

技术设计核心：

1.  Maple Gateway 自身承担统一网关和反向代理能力
2.  不强制依赖 Nginx
3.  数据平面与控制平面分离
4.  请求主链路使用内存路由表，避免逐请求查询数据库
5.  Domain → Tenant → Service → Deployment → Version → Instance → Node
6.  原生考虑 Load Balancing、Failover 与 Canary Traffic
7.  Container Manager 管实例生命周期，Maple Gateway 管流量
8.  同时支持 Docker 部署和 Linux Binary 部署
