    # Canary 测试容器

Gateway 的 `docker-compose.yml` 中。

# 服务端口

| 服务 | 端口 | 说明 |
|------|------|------|
| Maple Gateway HTTP | 80 | HTTP 数据平面 |
| Maple Gateway HTTPS | 443 | HTTPS 数据平面 |
| Management API | 8090 | 后端管理 API |
| Frontend | 5173 | React 管理后台 |
| Metrics | 9090 | Prometheus Metrics |
| Container Manager | 8100 | 接收 Gateway 部署意图 / 状态查询 |
| Node Agent | 8200 | 面向 CM 的容器操作（仅内网） |
| PostgreSQL | 5432 | 数据库 |
| Redis | 6379 | 辅助缓存 |

生产环境：

-   80 / 443：对外流量入口
-   8090：Management API，限制内部访问
-   5173：开发端口，生产构建后不直接暴露
-   9090：仅监控网络访问
-   8100 / 8200：控制面内部端口，禁止暴露公网
-   5432 / 6379：禁止暴露公网

# 与 Container Manager 的边界

控制面由 **Container Manager（CM）** 与 **Node Agent** 两个独立进程组成，
与 Maple Gateway 同仓库、同 Go module，但独立部署：

-   **Container Manager**（`cmd/containermanager`）：编排器。接收 Gateway 下发的部署期望态，
  与实际态对账，向各节点 Node Agent 下发容器操作。自己**不碰 Docker**。
-   **Node Agent**（`cmd/nodeagent`，每节点一个）：**唯一直连本机 Docker Engine** 的组件，
  在其上创建/启停/删除容器，并把容器与资源状态回报给 CM。

Maple Gateway 不负责：

-   创建 Container
-   删除 Container
-   Pull Image
-   Start / Stop Container
-   Container CPU / Memory 管理
-   Node 生命周期管理
-   Deployment 实际执行

这些属于 Container Manager（经 Node Agent 落地）。

Maple Gateway 负责：

-   接收实例状态
-   接收 Node 状态
-   Service Discovery
-   路由缓存
-   Reverse Proxy
-   Load Balancing
-   Health Awareness
-   Failover
-   Canary Traffic
-   Rolling Update 流量控制
-   Blue / Green 流量切换

关系（控制下行、状态上行，方向不混用）：

``` text
   Maple Gateway          （路由权威；下发部署意图 / 接收状态）
        │  部署意图 ▼            ▲ 状态上报
        ▼                        │
 Container Manager        （编排；不碰 Docker）
        │  容器操作 ▼            ▲ 容器/资源状态
        ▼                        │
   Node Agent             （每节点一个；唯一 Docker 触点）
        │
        ▼
  Docker Engine
```

实例锚点：容器标签 `maple.instance_id` = Gateway `instances.id`（同 UUID），保证一一对应。
详细契约见 `docs/Container-Manager-集成契约.md`。

# Maple Gateway 项目结构原则

1.  `server/` 统一放置 Go 后端、Gateway Core 和 Management API。
2.  `frontend/` 独立放置 React 管理后台，前后端完全分离。
3.  Gateway 数据平面与 Management API 虽然同属 `server/`，但在
    `internal/` 中保持模块解耦。
4.  `proxy/` 负责 Reverse Proxy，不依赖 React Frontend。
5.  `router/` 负责 Domain → Tenant → Service → Instance 路由。
6.  `cache/` 保存内存 Route Cache，请求主链路不逐请求查询 PostgreSQL。
7.  `loadbalancer/` 只从 Healthy Instance Pool 中选择实例。
8.  `health/` 与 `failover/` 管理实例健康状态和故障摘除。
9.  `traffic/` 统一处理版本权重与流量策略。
10. `canary/` 基于 Traffic Policy 实现金丝雀流量控制。
11. Container Manager 管 Container 生命周期，Maple Gateway 不直接控制
    Docker Engine。
12. PostgreSQL 保存持久化配置，Redis 只作为辅助组件。
13. 不要求 Nginx 作为 Maple Gateway 的必要前置层。
14. 前端只调用 Management API，不参与 Gateway Data Plane。
15. Docker Compose 只用于 Maple Gateway 自身依赖和开发测试环境。
16. 生产 Tenant Container 不写死在 Maple Gateway Compose 文件中。
17. 后端模块采用 `handler → service → repository` 结构，保持职责清晰。
18. 项目结构优先保持简单，不引入 Kubernetes 风格的过度抽象。
