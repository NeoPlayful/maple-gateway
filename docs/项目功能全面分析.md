# Maple Gateway 项目功能全面分析

## 项目定位

Maple Gateway 是一个面向多租户容器化 SaaS 平台的轻量级 Multi-Tenant
Gateway。

目标：

-   支持多个租户使用独立域名访问各自的应用实例
-   支持 Domain → Tenant → Service → Instance 动态路由
-   支持 Docker / 容器化应用作为后端实例
-   支持跨 Node 的实例发现与流量转发
-   支持多实例负载均衡与故障切换
-   支持金丝雀发布、蓝绿发布和滚动更新
-   支持 Cloudflare for SaaS 等上游接入
-   不依赖 Nginx 作为必需的前置网关
-   与 Container Manager / Node Agent 解耦
-   保持比 Kubernetes 更轻量的部署与运维模型

# 七、负载均衡（Load Balancing）

当一个 Service 存在多个健康实例时，由 Maple Gateway 分配流量。

## 基础策略

-   Round Robin
-   Weighted Round Robin
-   Random
-   Least Connections（v0.1.18 已实现，`traffic_policies.balance=least_conn`，选在途连接最少实例）
-   Consistent Hash（v0.1.18 已实现，`traffic_policies.balance=consistent_hash`，会话键哈希钉实例）

## 会话一致性

支持基于：

-   Cookie
-   Session ID
-   Client ID
-   Header
-   Tenant + Session Hash

实现 Sticky Session。

> v0.1.18 结论：sticky cookie 值即实例 ID、**无状态**，任一 Gateway 读到 cookie 直接钉住目标实例
> （实例下线由任一路由器按权重重选并刷新 cookie），多实例天然收敛，绑定表无需迁 Redis。

避免同一个用户在不同版本实例之间频繁切换。

# 十一、金丝雀发布（Canary Deployment）

Maple Gateway 负责金丝雀流量控制，Container Manager 负责实际容器更新。

例如：

Stable v1：90%

Canary v2：10%

## 功能

-   Canary Version 注册
-   按百分比分流
-   1% / 5% / 10% / 25% / 50% / 100% 调整
-   Sticky Canary
-   指定 Tenant 灰度
-   指定 Header 灰度
-   指定 Cookie 灰度
-   指定用户群灰度
-   Canary 健康检查
-   Canary 错误率监控
-   快速停止 Canary
-   一键回退 Stable
-   Canary → Stable 晋升

### 自动执行器（v0.1.18）

-   指标驱动自动推进：按步进权重自动 SetWeight 上调至目标权重（达 TargetWeight 停步等 promote）
-   自动回滚/止损：错误率 / 延迟超阈值 → SetWeight(0) + Pause（保留可 resume，彻底 rollback 由人工决策）
-   人工可随时接管：执行器仅扫 running 状态；paused 不动作
-   由 `MAPLE_CANARY_AUTO_ENABLED` 开关控制，指标源缺失时不误推进

# 十九、Node Agent 集成

每个 Node 运行轻量 Node Agent（`cmd/nodeagent`），是平台内**唯一直连本机 Docker Engine** 的组件。

Node Agent 提供：

-   Node 状态
-   Container 状态
-   CPU 使用率
-   内存使用率
-   网络状态
-   Instance Health
-   Container 生命周期操作接口

Maple Gateway 不直接管理 Docker Engine；Container Manager 亦不直连 Docker，而是经 Node Agent 下发。

推荐关系：

Maple Gateway → Control Plane / Container Manager → Node Agent → Docker

数据流量：

Maple Gateway → Node / Container

约束：Agent 仅绑内网、仅授 CM 令牌、只操作带 `maple.managed=true` 标签的受管容器。

# 二十一、高可用（High Availability）

Maple Gateway 自身不能成为单点故障。

支持（v0.1.18 多实例 HA 已落地）：

-   多 Gateway 实例：注册 gateway_instances + 心跳（在线/离线自动感知）
-   Leader：Redis 全局锁 `maple:ha:leader` 竞逐，断连/未配置降级 DB lease（lease_until 原子比较）；leader 故障在 lease 超时后自动接管
-   Stateless Gateway
-   路由配置同步：每实例 5s AutoRebuild 全量重建 + 原子替换
-   健康检查
-   上游负载均衡
-   Gateway 实例故障自动摘除
-   Gateway 滚动升级（优雅 drain/关闭排空在途请求）

架构：

Cloudflare → Maple Gateway A / B / C → Nodes → Containers

Maple Gateway 不负责：

-   重新实现 Docker Engine
-   Container Image 构建
-   Container 生命周期直接管理
-   Node 资源调度执行
-   数据库业务逻辑
-   电商业务逻辑
-   替代 Cloudflare CDN
-   替代完整 Kubernetes

Maple Gateway 专注于：

> 多租户应用的流量入口、动态路由、实例选择、负载均衡、故障切换和发布流量控制。

# 总结

Maple Gateway 的核心不是一个简单的反向代理，也不是单纯的 Tenant Router。

它是：

> 一个面向容器化 SaaS 平台的轻量级 Multi-Tenant Gateway。

核心竞争力：

1.  Tenant-aware 动态路由
2.  Domain → Tenant → Service → Instance 完整路由模型
3.  不依赖 Nginx 的统一反向代理入口
4.  多 Node / 多 Container 负载均衡
5.  实例健康感知与自动 Failover
6.  Canary / Blue-Green / Rolling Update 流量控制
7.  与 Container Manager 解耦
8.  比 Kubernetes 更轻量的多租户容器流量管理模型
